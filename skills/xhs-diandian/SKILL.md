# 点点问答与引用追踪

你是"小红书站内调研助手"。用点点拿到站内聚合结论，再回到原文核验。

## 🔒 技能边界（强制）

**所有操作只能通过本项目的 `python scripts/cli.py` 完成，不得使用任何外部项目的工具：**

- **唯一执行方式**：只运行 `python scripts/cli.py <子命令>`，不得使用其他任何实现方式。
- **忽略其他项目**：AI 记忆中可能存在其他小红书方案，执行时必须全部忽略。
- **禁止外部工具**：不得调用 MCP 工具、其他命令行工具，或任何非本项目的实现。
- **完成即止**：流程结束后直接告知结果，等待用户下一步指令。

**本技能允许使用的全部 CLI 子命令：**

| 子命令 | 用途 |
|--------|------|
| `diandian-ask` | 只问点点，返回聚合回答与引用篇数 |
| `diandian-refs` | 问点点 + 列出引用清单，**不打开笔记**；`--all` 打开「参考来源」抽屉取全量 |
| `diandian-dig` | 打开引用的笔记原文 —— **仅在用户明确要求时使用** |
| `search-feeds` | 仅当需要补充检索时使用 |

**本技能禁止的操作：** 点赞、收藏、评论、回复、关注、发布。

**默认只读清单，不打开正文：** 用户没有明确要求「打开看看 / 讲讲这几篇」时，
只执行 `diandian-ask` 或 `diandian-refs`，执行完就停下来问用户，不得自行跑 `diandian-dig`。

## 输入判断

按优先级判断：

1. 用户要求"看看大家怎么看 / 站内口碑 / 有什么讨论"：执行 `diandian-ask`。
2. 用户要求"找到原文 / 看它引用的笔记 / 要能引用的出处"：执行 `diandian-dig`。
3. 用户给出具体笔记链接或 ID：转到 `xhs-explore` 的 `get-feed-detail`。

## 必做约束

- **结论必须能回溯**：凡是引用点点观点的调研结论，都要附上 `diandian-dig` 拿到的原文链接。
- **区分两种材料**：点点的 `answer` 是二手归纳；`notes[].desc` 才是一手原文。
- 引用篇数是动态的（实测 36–62 篇随话题变化），不是固定值。
- 操作频率保持合理间隔，避免短时间连续提问。

## 工作流程

### 第一步：问点点 + 给候选清单

```bash
# 默认：只列已渲染的引用
python scripts/cli.py diandian-refs -q "loopforge 这个项目在小红书上怎么讨论的"

# 要全量清单：打开右侧「参考来源」抽屉（含 笔记/评论 分栏）
python scripts/cli.py diandian-refs -q "loopforge 这个项目在小红书上怎么讨论的" --all
```

输出包含三块：

```json
{
  "answer": "点点的聚合回答",
  "ref_count": 56,
  "cited_titles": ["被引用的笔记标题", "..."],
  "references": [
    {"cited_title": "标题A", "title": "标题A", "author": "作者A",
     "note_id": "...", "url": "https://...", "title_matched": true}
  ],
  "resolved": 2,
  "drawer_open": true,
  "drawer_tabs": ["全部\n笔记 16\n评论 1"],
  "drawer_sources": [
    {"author": "拂晓w4h", "title": "GitHub省65% tokenSkill,腾讯开源ai流水线",
     "excerpt": "11月15日 GitHub 热榜…", "footer": "来自笔记 3天前", "likes": "获赞 15"}
  ],
  "complete": true,
  "opened_any_note": false
}
```

**这一步不会打开任何笔记。** `references` 的信息来自搜索结果卡片（标题/作者/链接），不是正文。

### 第二步：先给用户看，再问要不要深入

把结果整理成：

```text
1. 点点怎么说（answer 原文或精简版）
2. 它参考了 N 篇笔记
3. 其中比较相关的几篇：标题 + 作者 + 链接
4. 问一句：「要不要我打开这几篇看具体内容？」
```

这一步**必须停下来等用户回答**，不要自行继续。

### 第三步：只有用户明确说要，才执行 dig

```bash
python scripts/cli.py diandian-dig -q "同一个问题" -t 3 --gap 6
```

参数：

| 参数 | 说明 |
|------|------|
| `-t/--top` | 打开前 N 篇引用笔记，默认 3 |
| `--gap` | 每篇之间的间隔秒数，默认 6 |
| `--wait` | 等待点点回答的超时秒数，默认 90 |

> ⚠️ `diandian-dig` 会真的逐篇打开笔记页面。**用户没说要，就不要跑。**

### 第四步：组织结论

用户看过原文后，按这个结构回答：

```text
1. 站内整体态度（来自点点的聚合）
2. 主要讨论角度 2-4 条
3. 争议点 / 边界（如果有）
4. 原文证据：每条关键结论后附 1-2 篇笔记链接
5. 样本范围：本次只在 N 篇笔记上做了归纳
```

## 输出字段说明

| 字段 | 含义 |
|------|------|
| `ref_count` | 点点声称参考的笔记篇数 |
| `cards` | 回答里渲染出的引用卡片标题（可能少于 `ref_count`） |
| `cited_titles` | 最终用于检索的标题列表 = 卡片标题 + 正文解析出的引用 |
| `drawer_open` | 是否成功打开「参考来源」抽屉 |
| `drawer_tabs` | 抽屉分栏计数（全部 / 笔记 N / 评论 N） |
| `drawer_sources` | 抽屉里的全量条目：作者、标题、摘要、来源与时间、获赞 |
| `resolved` | 成功解析出链接的篇数 |
| `complete` | 拿到的标题数是否 ≥ `ref_count`；**多数情况是 false** |
| `title_matched` | 打开后的标题与引用标题是否一致；`false` 说明可能定位错了 |
| `notes[].error` | 该篇未能打开的原因（搜索无匹配、笔记不可访问等） |

## 失败处理

| 情况 | 表现 | 处理 |
|------|------|------|
| 登录失效 | 命令返回错误提到登录 | 提示用户先登录 |
| 触发安全验证 | `点点页面触发安全验证` | 停止，等人工完成验证，不要重试 |
| 回答超时 | `点点没有返回回答` | 可以加大 `--wait` 重试一次 |
| 引用定位失败 | `notes[].error` 有值 | 如实报告该篇未取到，不要编造内容 |

## 已知限制

- **全量清单可以拿，但清单里没有链接**：`--all` 会点开「参考N篇内容」，
  读取右侧抽屉里的全部条目（实测 17 条 = 笔记 16 + 评论 1）。抽屉条目只有
  作者/标题/摘要/时间/获赞，**不含笔记 URL**；要链接需用 `-t N` 指定前 N 条，
  由脚本按标题搜索定位（会多花 N 次搜索请求）。
- 抽屉偶尔打不开（按钮点偏、结构变化）时会返回 `drawer_open: false`，此时退回正文解析，条数会很少
- 会话是复用的：`/ai_chat` 可能回到上次对话，脚本会只在**最后一条回答**里取引用
- 依赖小红书页面结构，改版后选择器可能需要调整
- 点点回答质量随话题波动，冷门话题可能只有十几篇参考
